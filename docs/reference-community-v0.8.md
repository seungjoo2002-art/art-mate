# v0.8 F-15 참고작 추천 · 커뮤니티 — 설계와 운영

> 작성: 2026-11-09 · 브랜치 `feature/v0.8-reference-community` · 리비전 `0008` (down_revision `0007`)
> 프론트 연동: [frontend-integration-v0.8.md](frontend-integration-v0.8.md) · DB: [database-design.md §3.22](database-design.md)

구현하지 않음: AI 직접 작품 평가, 합격률 예측, 이미지 모델 학습, 채팅, 팔로우·DM, 결제, 실시간 알림.

## 1. F-15 추천 알고리즘 (`reference-rule-v1`)

1. **학생 맥락**: v0.7 반복 약점 TOP 3 (승인 첨삭, 전체 범위, 작품 단위 집계), 주 실기 유형(프로필 → 작품 분포 순), 자주 하는 작업 목적.
2. **후보 (CandidateSource = `VerifiedExemplarSource`)** — 모두 SQL 조건:
   - 강사가 **그 약점 카테고리의 우수 사례로 확인**(`reference_artwork_reviews` ACTIVE)
   - 원작자의 **REFERENCE 동의가 유효**하고 범위가 이 학생에게 열림 (PLATFORM, 또는 같은 학원 ACTIVE 멤버)
   - 공유 이미지 ACTIVE, 작품 삭제 안 됨, **학생 본인 작품 제외**
3. **점수**: 약점 순위 `(약점 수 − 순위 + 1) × 10` + 같은 실기 유형 +5 + 같은 작업 목적 +2 (+ 최근 확인 미세 가중치)
4. **중복 제외·제한**: 작품당 1번(가장 높은 점수의 약점), 약점당 3개, 전체 9개.
5. **근거**: `VERIFIED_EXEMPLAR`, `MATCHES_WEAKNESS`, `SAME_PRACTICAL_TYPE`, `SAME_WORK_CATEGORY` 코드 + 문장. 강사의 참고 포인트(`note`)를 함께 보여 준다.
6. **스냅샷·중복 방지**: 결과를 `reference_recommendations`(set 단위)에 입력값과 함께 저장. 입력 지문(약점·실기 유형·작업 목적·후보 ID·동의 ID·이미지 ID)이 같으면 새로 만들지 않는다. 학생 단위 행 잠금으로 동시 새로고침도 묶음 1개.
7. **결과 없음**: 반복 약점이 없으면 `NO_REPEATED_WEAKNESS`, 검증된 사례가 없으면 `NO_VERIFIED_REFERENCES` — 억지로 채우지 않는다.

확장: 이미지 임베딩·AI 시각 분석은 새 CandidateSource 또는 점수 보정 단계로 붙인다. 단 **"우수하다"는 근거는 사람(강사)이 확인한 기록**이라는 원칙은 유지한다. 이번 버전은 모델 학습·유료 이미지 분석을 하지 않는다.

## 2. 우수성 검증

- 카테고리가 같다는 사실만으로 추천하지 않는다. 우수성 근거는 **강사 확인 기록 하나뿐**이다.
- 강사는 **담당 학생의 학원 연결 작품**만 확인할 수 있다 (비담당 403, 다른 학원·개인 작품 404). FINAL 사진 필요.
- 강사 확인용 후보 API는 승인된 첨삭에서 그 카테고리가 '잘한 점'(STRENGTH)으로 언급된 작품을 보여 줄 뿐 자동 확인하지 않는다.
- 확인 해제 시 그 확인을 근거로 한 학생별 추천 행을 삭제한다.

## 3. 공유·동의·원본 보호

| 항목 | 설계 |
| --- | --- |
| 기본값 | 모든 작품 비공개 |
| 목적별 동의 | `COMMUNITY`(게시) / `REFERENCE`(참고작 활용), 각각 범위 `ACADEMY`/`PLATFORM`, 작성자 표시 `NAME`/`ANONYMOUS`, 버전, `SELF`/`GUARDIAN` |
| 변경 | 기존 동의 철회(`CHANGED`) + 새 동의 (이력 보존) |
| 원본 보호 | 원본(artworks 버킷)의 URL은 공유 화면에 쓰지 않는다. 동의 시 서버가 FINAL 대표 사진에서 **파생 이미지**(EXIF 회전 보정 → 긴 변 1600px → JPEG 재인코딩, EXIF·GPS·메타데이터 제거)를 만들어 **별도 비공개 버킷 `shared-artworks`** 에 저장 |
| 제공 방식 | 보는 사람의 토큰으로 짧은 Signed URL(기본 5분). Storage RLS `can_access_shared_image`가 이미지 ACTIVE + 유효 동의 범위(PLATFORM: 활성 프로필, ACADEMY: 그 학원 ACTIVE 멤버) + 커뮤니티 전용이면 게시물 ACTIVE를 다시 검사 |
| 경로 | `{무작위}/{image_id}.jpg` — 사용자·작품 ID를 넣지 않는다 (익명 공개 시 URL로 작성자 식별 방지; 테스트에서 발견해 수정) |
| 조회 | 피드·상세·추천·저장 목록 모두 **현재 유효한 동의**를 조인 → 철회 즉시 비공개 |

### 공유 철회 시 정리 (테스트로 검증)

| 철회 | 정리 |
| --- | --- |
| COMMUNITY | 동의 `revoked_at`, 게시물 `DELETED` → 피드·상세·좋아요·댓글·저장 목록에서 즉시 제외 |
| REFERENCE | 동의 `revoked_at`, 그 작품을 가리키는 **모든 학생의 참고작 추천·저장 행 삭제** |
| 남은 동의 없음 | 파생 이미지 `DELETED` + Storage 파일 삭제 (실패 시 `storage_cleanup_pending`으로 재시도) |
| 작품 삭제 | 모든 동의 `ARTWORK_DELETED` 철회 + 위 정리 |

## 4. 커뮤니티

- 게시물(작품당 1개, 본인 작품, COMMUNITY 동의 필요), 피드(실기 유형·작업 목적·학원 필터, 최신순, 페이지네이션), 상세, 수정·삭제(작성자).
- 좋아요·저장: 유니크 제약 + `ON CONFLICT DO NOTHING`, 좋아요 수는 원자적 UPDATE (동시 5회 → 1).
- 댓글: 1~1000자, 작성자만 수정·삭제, 숨김·삭제 시 댓글 수 보정.
- 신고: 게시물·댓글, 사유 6종, 본인 글 불가, 사람당 대상 1회(부분 유니크), 서로 다른 3명 미처리 신고 → 자동 숨김.
- 관리(시스템 ADMIN): 신고 목록, 처리(숨김/조치 없음), 기각(자동 숨김 복구), 게시물·댓글 숨김·복구, 처리 이력.
- 요청 제한(DB 기준, 서버 여러 대에서도 동일): 게시 하루 10, 댓글 10분 20, 신고 하루 20 → 429 + `Retry-After`.
- 학원 단위 관리(OWNER/MANAGER가 학원 공개 게시물 관리)는 이번 범위가 아니다.

## 5. 개인정보·보안 위험 (법적 검토 필요)

1. **미성년자 작품 공개**: 만 14세 미만은 법정대리인 동의가 필요하나 `GUARDIAN`은 자기 신고값이다. 보호자 확인 절차(본인인증 등) 설계 필요.
2. **제3자 제공 여부**: PLATFORM 공개 작품을 다른 학원 학생에게 참고작으로 보여 주는 것이 제3자 제공·공개에 해당하는지, 동의 문구의 고지 항목.
3. **저작권**: 학생 작품의 저작권은 학생에게 있다. 공유용 이미지 제공·참고작 추천에 대한 이용 허락 범위(비상업적 서비스 내 열람)를 약관에 명시해야 한다.
4. **강사 메모 공개**: 참고 포인트(`note`)는 원작자가 아닌 학생에게 보인다. 원작자에 대한 평가가 담길 수 있으므로 강사 가이드 필요.
5. **스크린샷·재배포**: Signed URL을 짧게 해도 화면 캡처는 막을 수 없다 (워터마크는 이번 범위 아님).
6. **보존**: 철회된 동의 이력은 증빙으로 보존, 게시물·댓글의 보존 기간 정책 미정.
7. **신고 악용**: 3건 자동 숨김은 집단 신고에 취약 → 관리자 검토로 복구 가능, 임계값은 운영 데이터로 조정.
