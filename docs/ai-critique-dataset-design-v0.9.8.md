# v0.9.8 AI 미대입시 첨삭 — 데이터셋 기반과 후속 설계

최종 목표: 학생 작품 이미지 + 실제 강사 피드백을 정확히 연결해 **전문가 첨삭 데이터**를 쌓고,
이후 대학별 합격작의 정량 특징·공식 실기 평가기준과 결합해 **목표 대학 맞춤 AI 첨삭**을 제공한다.

이번 버전에서 구현한 것: 단계별 사진 타임라인, 피드백 기준 이미지 연결, 학습 활용 동의, 데이터셋 최소 저장 구조
(구조화 레이블 테이블 포함), 관리자용 통계·가명 샘플 미리보기.
구현하지 않은 것: 이미지 특징 추출 엔진, 대학별 모델, 모델 학습, 유료 AI 호출.

하지 않는 것(범위 밖, 의도적으로 제외): 수정 전후 이미지 변화량·피드백 반영률 측정, 전후 비교 화면,
SSIM·LPIPS 등 전후 비교 지표를 핵심 평가로 쓰는 것, 합격 가능성·합격 확률 예측.

---

## 1. 단계별 사진 타임라인 (구현)

- 작품별 사용자 정의 단계(v0.9.7)는 그대로. 각 단계에 사진을 여러 장 계속 쌓는다(교체 아님, 단계당 기본 30장).
- 단계 안에서 **사진과 그 단계의 피드백(녹음·글 첨삭)을 올린 시각 순으로** 보여 준다. 작품 전체 피드백은 맨 아래 영역.
- 피드백 뒤에 사진을 올릴 필요는 없다. 올린 사진은 일반 단계 사진과 똑같다(대표 지정·사진 수·진행도 포함).
- 예전 "수정 사진(REVISION)" 데이터는 지우지 않는다. `kind`·`feedback_*_id`는 "어느 피드백 뒤에 올렸는지" 기록으로 남고,
  화면·집계에서는 일반 사진으로 취급한다(0015에서 대표 지정 제한 해제).
- 새 작품 기록·시험 모드 모두 같은 작품 상세 타임라인을 쓴다(시험 진행 화면의 사진·메모·녹음은 해당 단계에 연결).
- API: `GET /artworks/{id}/stage-history` 의 `stages[].timeline` = `[{type: PHOTO|FEEDBACK, at, photo|feedback}]`.

```
[STEP 1 스케치]  사진 3장  [사진 추가]
  10:00 사진
  10:15 사진
  10:20 선생님 피드백 (녹음)  └ 기준 사진: 10:15 사진 · 확인됨
  10:35 사진
  10:50 선생님 피드백 (글)    └ 기준 사진: 10:35 사진 · 확인 필요
[작품 전체 피드백]
```

## 2. 피드백 ↔ 기준 이미지 (구현)

| 항목 | 설계 |
|---|---|
| 저장 | `feedback_image_refs` (피드백 1개 ↔ 사진 N장, 최대 10, 순서 position). 같은 작품 사진만 (복합 FK) |
| 고르기 | 녹음·글 첨삭 화면에서 단계별 사진 썸네일로 여러 장 선택 → `reference_photo_ids` + `reference_confirmed` |
| 기본 제안 | 고르지 않으면 **그 시점** 같은 단계(전체 피드백이면 작품 전체)의 최신 사진을 `SUGGESTED`로 저장 |
| 확인 | 작품 화면 피드백 카드 아래 "맞아요"/"변경", 또는 `PUT .../image-refs {photo_ids, confirmed}` → `CONFIRMED` |
| 고정 | 생성 시점에 행으로 저장 → 이후 사진이 추가돼도 바뀌지 않음. 변경은 명시적 저장으로만 (확인 시각·확인한 사람 기록) |
| 전체 피드백 | 여러 단계의 사진을 함께 참조 가능 |
| 사진 삭제 | 연결 행은 남고 `photo_status=DELETED`로 표시 → 학습 샘플에서 제외 |
| STT·AI 요약 | 전사·요약은 원본 녹음·글 첨삭에 매달리므로 같은 연결을 그대로 노출 (`RecordingRead/FeedbackNoteRead/FeedbackRead.image_refs`). 기준 이미지 변경은 요약을 무효화하지 않음 |
| 상태 | `NONE` 없음 / `SUGGESTED` 제안(미확인) / `CONFIRMED` 확인. **확인된 것만 학습 데이터 조건** |
| 기존 데이터 (0015) | 피드백 시점 이전의 최신 사진을 `SUGGESTED`로만 백필. 시점 이전 사진이 없으면 `NONE`. 자동 확인 없음 |

현재 앱은 학생 앱이므로 "확인"은 피드백을 기록하는 학생이 한다(강사 화면이 생기면 강사 확인을 별도 필드로 추가: §4).

## 3. 학습 데이터셋 (최소 저장 구조 구현)

### 3.1 학습 샘플 (`TrainingSample`, `GET /admin/dataset/samples`, ADMIN 전용)

| 필드 | 출처 |
|---|---|
| sample_id, feedback_type | 녹음 / 글 첨삭 id |
| learner | 학생 id의 HMAC 가명 (`DATASET_PSEUDONYM_KEY`, 없으면 내보내기 503) |
| images[] (photo_id, 단계 id·이름, legacy 단계, 순서, 업로드 시각) | `feedback_image_refs` (확인됨, 삭제 안 된 사진) |
| feedback_stage | 피드백 단계 (null = 작품 전체) |
| practical_type, work_category, topic, exam_materials | `artworks` (`exam_materials` 0015 신규) |
| target_universities[] (우선순위·대학·학과) | `target_universities` (전형은 후속: §6) |
| raw_text | 글 첨삭 원문 |
| transcript, transcript_edited | STT 전사 최신본 (사용자 수정 여부) |
| ai_summary, ai_summary_status | 현재 AI 요약 |
| expert_verified | 학원 작품에서 **강사가** AI 요약을 확정(APPROVED, review_mode INSTRUCTOR) |
| labels[] | AI 요약 항목(origin AI) + `feedback_labels`(전문가·학생 레이블) — 원문과 분리 |
| feedback_created_at | 피드백 생성 시각 |
| consent_version, consent_age_band | 학습 활용 동의 |

### 3.2 샘플 조건 (`app/services/dataset.py` 한 곳에서 판단)

1. 학생의 유효한 학습 활용 동의(현재 버전, 철회 안 함). **만 14세 미만은 동의 자체를 받지 않음**(보호자 절차 전).
2. 기준 이미지 `CONFIRMED` + 삭제되지 않은 기준 사진 ≥ 1. `SUGGESTED`/`NONE`은 자동 등록하지 않음.
3. 강사 피드백: 글 첨삭은 출처 INSTRUCTOR, 녹음은 강사 동의를 학생이 기록(`CONSENT_REPORTED`).
4. 녹음은 STT 전사 존재.

`GET /admin/dataset/stats`: 후보 수·적격 수·제외 사유별 수 (`NO_DATASET_CONSENT`, `IMAGE_REF_NOT_CONFIRMED`,
`NO_ACTIVE_REFERENCE_PHOTO`, `NOT_INSTRUCTOR_FEEDBACK`, `INSTRUCTOR_CONSENT_NOT_REPORTED`, `NO_TRANSCRIPT`).

### 3.3 동의 (`dataset_consents`, `/dataset-consents/me`)

- AI 정리 동의와 별개, 선택. 생년월은 연령 구간 계산에만 쓰고 저장하지 않음. 철회하면 즉시 내보내기에서 빠짐.
- 남은 과제: 강사 본인의 학습 활용 동의(현재는 학생이 기록한 녹음 동의 상태로만 거름), 만 14세 미만 보호자 동의 절차,
  이미 내보낸 사본의 삭제 절차(동의 철회 시), 보관 기간.

## 4. 전문가 피드백 구조화 (`feedback_labels`, 저장 구조 구현)

| 필드 | 의미 |
|---|---|
| problem_type | 구도 COMPOSITION / 형태 FORM / 비례 PROPORTION / 원근 PERSPECTIVE / 명암 VALUE / 채색 COLOR / 질감 TEXTURE / 묘사 RENDERING / 완성도 FINISH / 시간 TIME_MANAGEMENT / 기타 (약점 카테고리와 같은 코드) |
| target_object | 지적 대상 사물 ("오른쪽 컵") |
| photo_id + region | 위치를 표시한 사진과 영역 {x, y, w, h} (0~1 정규화) |
| description | 문제의 구체적인 내용 |
| recommendation | 권장 수정 방향 |
| severity | 중요도 1 낮음 · 2 보통 · 3 높음 |
| evidence_segment_ids | 원문 근거 (전사·글 첨삭 문장 index) |
| origin | AI 추정 / EXPERT 강사 작성 / STUDENT 학생 정리 |
| verification | UNVERIFIED / CONFIRMED(강사 확인, verified_by·at 필수) / REJECTED(학습 제외, 기록 보존) |
| summary_id | AI 요약에서 나온 레이블이면 그 요약 |

원칙: 원문(피드백·전사)은 수정하지 않고 레이블만 따로 쌓는다. **언급되지 않은 항목은 행이 없을 뿐 "정상"이 아니다**
(학습 시 미언급 = 결측으로 처리, 음성 레이블로 쓰지 않음). AI 레이블은 강사가 확인하기 전까지 UNVERIFIED.

후속 구현: 강사용 레이블 작성·확인 화면(사진 위 영역 표시), AI 요약 항목 → `feedback_labels(origin=AI)` 이관 작업,
레이블러 간 일치도(같은 피드백을 두 명이 레이블링) 측정.

## 5. 이미지 정량 분석 엔진 (설계만)

### 5.1 파이프라인

```
원본 사진 ─▶ 전처리 ─▶ 분할·검출 ─▶ 특징 추출(모듈별) ─▶ image_features (버전·신뢰도 포함)
            (화지 검출·        (화지 안 객체·      (구도/비례/투시/명암/       ▲
             투시 보정·         배경 분리,         색채/묘사/주제부)          │
             색·노출 보정)      소실선 검출)                                   재현성 검증 셋
```

- 배치 작업으로만 실행(AI 작업 큐와 같은 워커 구조, 업로드 경로에 넣지 않음). 결과는 원본과 분리 저장.
- 테이블(안): `image_analyses(id, photo_id, pipeline_version, status, quality_flags, created_at)`,
  `image_features(analysis_id, feature_key, value, unit, confidence, model_version)` — 특징을 키-값으로 두어 추가가 쉬움.
- `quality_flags`: 화지 미검출, 과도한 기울기(> 15°), 반사·그림자, 노출 클리핑, 해상도 부족 → 해당 특징은 신뢰도 낮음/결측.

### 5.2 전처리 (촬영 오차 줄이기)

| 단계 | 방법 | 이유 |
|---|---|---|
| 화지 검출·투시 보정 | 사각형 윤곽 검출(Canny + 다각형 근사) 또는 문서 분할 모델 → 호모그래피로 정면화, 화지 비율로 크롭 | 비스듬한 촬영이 구도·비례·투시 특징을 왜곡 |
| 렌즈 왜곡 | 휴대폰 EXIF 기반 보정 가능 시 적용, 아니면 무시하고 신뢰도 하향 | 직선 수렴 계산 오차 |
| 화이트밸런스·노출 | 화지 여백(흰 종이)을 기준 백색으로 정규화, 히스토그램 클리핑 비율 기록 | 조명 색온도·밝기가 명암·색채 특징을 지배 |
| 해상도 정규화 | 긴 변 1024/2048 두 스케일 | 에지·질감 지표의 해상도 의존성 |

### 5.3 특징별 알고리즘

| 영역 | 특징 | 알고리즘 / 필요 모델 | 촬영 조건 오차 | 검증 |
|---|---|---|---|---|
| 1 구도 | 객체 위치(정규화 중심), 점유율, 여백(상하좌우 비율), 시각적 무게중심 | 전경 분할(SAM 계열 + 화지 마스크), 객체 검출(오픈어휘 검출기), 무게중심 = 명도 대비·채도·에지 밀도 가중 질량중심, 3분할·중심 거리 | 투시 보정 실패 시 위치 편향, 화지 일부 잘림 | 같은 작품 다른 각도 재촬영 반복성(ICC), 강사 구도 지적과의 상관 |
| 2 비례 | 객체 가로세로 비, 객체 간 상대 크기, 좌우 대칭성 | 분할 마스크의 최소 외접 사각형·주축(PCA), 대칭: 축 반사 후 IoU | 기울기·렌즈 왜곡에 민감 | 정답 실측(석고·정물 사진 대비) 오차, 반복성 |
| 3 공간·투시 | 직선 수렴도, 소실점 위치, 객체 겹침(앞뒤) 관계 | LSD/Hough 선분 → RANSAC 소실점, 수렴 잔차; 겹침: 분할 마스크 경계·깊이 추정(단안 깊이 모델) 순서 | 사진 자체의 투시(촬영 각도)가 그림 속 투시와 섞임 → 정면화 필수 | 합성 투시 도형 테스트 셋, 강사 원근 지적과의 일치 |
| 4 명암 | 명도 분포(L* 히스토그램·분위수), RMS 대비, 국소 대비(타일별 표준편차), 명도 단계 수 | CIELAB L*, 다중 스케일 국소 대비, 명도 클러스터링(k-means) | 조명·노출·그림자에 가장 민감 | 그레이 카드 포함 촬영 셋으로 보정 전후 편차, 강사 명암 지적과의 상관 |
| 5 색채 | CIELAB 색 분포, 채도(C*), 색상 다양성(색상각 엔트로피), 주조색 | Lab 변환(화지 기준 백색 보정 후), 색상 히스토그램 엔트로피, 팔레트 추출 | 색온도·화이트밸런스, 카메라 보정 | 컬러 체커 촬영 ΔE 오차, 반복성 |
| 6 묘사 | 에지 밀도, 질감(GLCM·LBP·웨이블릿 에너지), 국소 디테일(고주파 비율) | Canny/구조 텐서, 다중 스케일 질감 통계, 영역별(주제부·배경) 분리 계산 | 초점 흐림·노이즈·해상도 | 블러 합성 민감도 곡선, 재촬영 반복성 |
| 7 주제부 강조 | 주제부-배경 명도·채도·에지 대비, 크기 비, 위치 | 주제부 = 검출 객체 중 최대 점유/중앙 근접 또는 강사 레이블 영역; 대비 = 영역 간 차이 | 주제부 오검출 | 강사가 지정한 주제부 영역과의 IoU |

공통: 모든 특징에 `confidence`(품질 플래그·모델 신뢰도), `pipeline_version`을 붙이고, 버전이 바뀌면 재계산한다.
특징은 "좋다/나쁘다" 판정이 아니라 **측정값**이며, 판단은 §6의 기준(대학별 분포·공식 기준)과 강사 레이블로 한다.

### 5.4 검증 계획

1. **반복성**: 같은 작품을 조명·각도·기기를 바꿔 5회 촬영 → 특징별 ICC ≥ 0.8 을 채택 기준으로.
2. **정확성**: 합성 도형·실측 정물·그레이 카드/컬러 체커 셋으로 절대 오차.
3. **타당성**: 강사 확인 레이블(problem_type·region)과 특징의 상관·분류 성능(AUC). 미언급 항목은 평가에서 제외.
4. 전후 비교 지표(SSIM·LPIPS)는 핵심 평가에 쓰지 않는다(필요 시 촬영 중복 검출 같은 보조 용도만).

## 6. 대학별 맞춤 AI 첨삭 (설계만)

| 구성 | 테이블(안) / 내용 |
|---|---|
| 대학·학과·전형·연도 | `universities`, `admission_tracks(university, department, track, year, practical_type)` |
| 시험 유형·제시물 | `exam_prompts(track, year, topic, materials[], conditions, time_limit)` — 학생 작품의 `topic/exam_materials`와 같은 형식 |
| 합격작 DB | `accepted_works(track, year, image, source, license, verified_by)` — 출처·이용 허락·검증자 필수 (저작권·초상권) |
| 합격작 특징 분포 | `track_feature_stats(track, feature_key, n, mean, sd, quantiles, pipeline_version)` — §5 특징을 트랙별로 집계 |
| 공식 평가항목·가중치 | `official_criteria(track, year, criterion, weight, source_url, published_at)` — 공식 배점 |
| 전문가 추정 가중치 | `expert_criteria_estimates(track, criterion, weight, estimator, rationale)` — **공식 배점과 분리**, 화면에도 구분 표시 |
| 작품 성향 유사도 | 학생 작품 특징 벡터 ↔ 트랙 분포의 표준화 거리(z-score), 임베딩(이미지 인코더) 코사인 유사도 — "경향 비교"로만 표현 |
| 기초 실기 역량 | 대학과 무관한 공통 축(구도·비례·명암·묘사 등)을 강사 확인 레이블로 학습한 역량 점수 + 신뢰구간 |
| 첨삭 근거 | 각 첨삭 문장에 근거 연결: (공식 기준 / 전문가 추정 / 합격작 분포 / 강사 레이블) + 이미지 영역 |
| 신뢰 수준 | 표본 수(n), 특징 신뢰도, 모델 보정(calibration)으로 높음/보통/낮음 — 낮으면 대학별 첨삭 대신 기초 역량 첨삭만 |

원칙: **합격 가능성·합격 확률은 예측하지 않는다.** "목표 대학 합격작들과 비교했을 때 명암 대비가 분포 하위 20% 범위"처럼
측정·근거 중심으로 표현하고, 근거 출처(공식/추정/통계)를 항상 함께 보여 준다.

## 7. 후속 개발 계획

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| P1 (다음) | 강사 화면: 학원 작품 피드백의 기준 이미지 확인, `feedback_labels` 작성·확인(영역 표시) | 강사 확인 레이블 누적, 레이블러 간 일치도 측정 |
| P2 | 전처리·품질 플래그 워커 (화지 검출·투시·색 보정), 특징 1·4·5 (구도·명암·색채) | 반복성 ICC ≥ 0.8, 품질 플래그 정확도 |
| P3 | 특징 2·3·6·7 (비례·투시·묘사·주제부), 강사 레이블과의 타당성 평가 | 특징별 AUC 리포트 |
| P4 | 합격작·평가기준 DB (출처·이용 허락 확보), 트랙별 분포 | 트랙당 최소 표본 수 정책 |
| P5 | 기초 역량 모델 → 대학별 첨삭 (근거·신뢰 수준 표시), 유료 AI는 비용·동의·ZDR 검토 후 | 강사 블라인드 평가에서 유용성 확인 |

각 단계는 운영 DB 마이그레이션·환경변수·유료 호출 전에 승인을 받는다.
