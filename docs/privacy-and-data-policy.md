# 개인정보·데이터 정책 (미성년 학생 고려)

> 상태: v0.2 기준 현황 + 후속 구현 항목. 법률 검토 전 초안이며, 정책 확정은 운영 책임자와 협의합니다.
> 참고 법령: 개인정보 보호법(특히 제22조의2 아동의 개인정보 보호 — 만 14세 미만 법정대리인 동의).

## 1. v0.2에서 저장하는 개인정보

| 데이터 | 저장 위치 | 비고 |
| --- | --- | --- |
| 이메일, 비밀번호(해시) | Supabase Auth (`auth.users`) | **ART MATE DB에 저장하지 않음**. API 응답의 `email`은 토큰에서 읽음 |
| 표시 이름 (`display_name`) | `profiles` | 실명 강제하지 않음 (닉네임 허용) |
| 사용자 유형, 활성 상태 | `profiles` | |
| 프로필 이미지 경로 | `profiles.avatar_path` | 파일 자체는 Storage (업로드는 v0.3) |
| 학원 소속·역할, 가입 요청 메시지 | `academy_memberships`, `academy_join_requests` | 요청 메시지 300자 제한 |

수집하지 않는 것: 생년월일, 전화번호, 학교, 주소, 보호자 정보 (필요해지는 버전에서 동의 절차와 함께 추가).

## 2. v0.2에 적용된 보호 장치

- 사용자 식별은 검증된 JWT `sub`로만 수행, 요청 본문의 `user_id` 불신
- 본인 프로필만 수정 가능, `user_type`·`is_active` 변경 불가 (권한 상승 방지)
- 학생 역할은 다른 학생 목록을 볼 수 없음 (멤버 목록은 강사 이상)
- 다른 학원 데이터 접근 시 404 (존재 여부 비노출), 시스템 ADMIN도 학원 소속이 아니면 학원 내부 데이터 접근 불가
- 가입 요청 목록에는 신청자 이메일을 포함하지 않음 (표시 이름·아바타만)
- 모든 앱 테이블 RLS 활성화 (Supabase Data API로 직접 접근 차단), service_role 키 미사용
- 토큰·이메일·개인정보를 로그에 남기지 않음 (접근 로그는 method/path/status/시간만)

## 3. 후속 구현 항목

### 3.1 미성년자 동의 (v0.3 우선순위 높음)
- [ ] 가입 시 연령 구간 확인 (생년월일 대신 "만 14세 미만 여부" 체크로 최소 수집)
- [ ] 만 14세 미만: 법정대리인 동의 절차 (보호자 이메일/휴대폰 인증) 완료 전 기능 제한
- [ ] `consent_records` 테이블 (append-only): 개인정보 수집·이용, 작품 사진 촬영·저장, 음성 녹음, AI 처리, 학부모 리포트 발송 — 항목별 동의/철회 이력과 약관 버전
- [ ] 동의 철회 시 해당 기능 즉시 중단 (예: 음성 녹음 동의 철회 → 녹음 버튼 비활성)

### 3.2 작품 공개 범위 (작품 업로드 버전에서)
- [ ] 기본값 **비공개**: 학생 본인 + 소속 학원 강사·관리자만 열람
- [ ] 학원 내 공유(우수작 등)는 학생(미성년자는 보호자) 동의가 있을 때만
- [ ] 외부 공개(포트폴리오 링크, 커뮤니티)는 v0.x에서 별도 동의 + 학생 실명·얼굴·학교명 노출 금지 가이드
- [ ] Storage 버킷 private, 짧은 만료 signed URL만 사용, 경로 `academies/{academy_id}/...`

### 3.3 탈퇴·삭제
- [ ] 회원 탈퇴 API: 프로필 익명화(`display_name` → "탈퇴한 사용자"), `is_active=false`, Supabase Auth 계정 삭제 요청
  - Supabase 계정을 삭제하면 `profiles`가 FK `ON DELETE CASCADE`로 삭제되고 소속·가입 요청도 함께 삭제됨 (v0.2 스키마)
  - 작품·첨삭이 생기는 버전부터는 학원 보존 정책과 충돌하므로, 즉시 삭제 대신 "익명화 + 보존기간 후 파기"로 전환 필요
- [ ] OWNER 탈퇴: OWNER 양도 기능(v0.3) 선행 필요. 현재는 OWNER 탈퇴 불가
- [ ] 학원 탈퇴 후 데이터: 소속 행은 `LEFT`로 보존 (재가입 시 재사용). 작품 데이터 보존기간 정책 확정 필요 (안: 퇴원 후 1년)
- [ ] 계정 비활성화(`is_active=false`) 운영 도구: v0.2에는 API 없음 (DB에서 직접). v0.3에서 ADMIN API 추가
- [ ] 정보주체 요청(열람·정정·삭제) 처리 절차와 담당자 지정

### 3.4 운영·보안

- [ ] 개인정보 처리방침·이용약관 페이지, 버전 관리
