## 2. 정책 검토

### 2.1 근거

| 출처 | 내용 |
| --- | --- |
| OpenAI Under-18 API guidance (원문 확인) | "should not use OpenAI services to process any personal data of children under 13 **or the applicable age of digital consent** … without first implementing zero data retention in our API". 18세 미만에게는 안전하고 연령에 맞는 콘텐츠, **연령에 맞는 AI 안내**, 연령에 맞는 콘텐츠 필터, 모니터링·신고 경로, 필요 시 연령 확인, 최신 주력 모델. **보호자 동의 요구는 이 문서에 없음** |
| OpenAI 비즈니스 약관 | **원문 미확인** (공식 사이트가 자동 조회를 막고, 웹 아카이브 조회는 권한상 차단). 보호자 허락 조항이 있는지 운영자가 직접 확인해야 함 |
| 개인정보 보호법 제22조의2 | 만 14세 미만 개인정보 처리 시 법정대리인 동의 + 동의 확인. 아동에게 이해하기 쉬운 양식·언어로 고지. **만 14세 이상은 본인 동의 가능** |
| 같은 법 제28조의8 | 국외 이전은 별도 동의 또는 계약 이행을 위한 처리위탁·보관 등 법정 근거 필요. 근거·이전 정보는 처리방침에 공개 |

### 2.2 "해당 지역의 디지털 동의 연령"은 한국에서 몇 세인가 ⚖️

- OpenAI 문서는 연령을 정하지 않고 **각 지역의 디지털 동의 연령**을 따르라고 한다.
- 한국에서 본인이 개인정보 처리에 동의할 수 있는 연령은 개인정보 보호법상 **만 14세**다.
- 따라서 이 구현은 **만 14세 미만을 ZDR 선행 대상**으로 본다. 만 13세 미만으로만 보면 13세가 빠지므로, 더 보수적인 쪽을 택했다.
- **확정이 아니다** → 법률 검토로 확인할 항목.

### 2.3 결정된 이용 구조

| 연령 (생년월로 판정) | 동의 | 외부 전송 조건 | 운영 스위치 (기본) |
| --- | --- | --- | --- |
| 만 18세 이상 | 본인 | 동의 즉시 | — |
| **만 14~17세** | **본인** (국내법) | 운영자가 OpenAI 미성년자 보호조치를 확인하고 연령대를 열었을 때 | `AI_TEENS_ENABLED=false` |
| 만 14~17세 (선택) | 본인 + 보호자 확인 | OpenAI 약관이 보호자 허락을 요구한다고 확인되면 | `AI_TEEN_GUARDIAN_REQUIRED=false` |
| 만 14세 미만 | 법정대리인 동의·확인 | 운영자 허용 **그리고** OpenAI ZDR 승인 **그리고** 법정대리인 확인 | `AI_UNDER14_ENABLED=false`, `AI_ZDR_APPROVED=false` |

- 판정은 API(요청 시)와 Worker(보내기 직전) 두 곳에서 한다.
- 운영자가 스위치를 다시 끄면 대기 중인 작업은 보내기 직전에 취소된다(전송 없음). 대본은 영향 없음.
- 학년은 판정에 쓰지 않는다.

## 4. 전송 데이터 최소화

- 보내기 전에 **보낼 사본에서만** 가린다: 전화번호(휴대폰·지역번호)·이메일·주민등록번호·카드번호·URL, 학생 본인 실명·닉네임(두 글자 이상) → `[전화번호]`·`[학생]` 등 (`app/services/ai_redaction.py`).
- 구간 번호·시각은 그대로다. 근거 대조도 가린 문장으로 한다.
- 원문 대본, 요약 근거 연결, 성장 분석 연결은 바뀌지 않는다 (테스트).
- 가린 횟수만 로그에 남긴다(내용 없음).
- **한계 — 익명화가 아니다**:
  - 강사·다른 학생 이름, 학교·학원명, 지역, 고유명사, 맥락(가족·진학 이야기)은 남을 수 있다.
  - 음성 인식이 이름을 다르게 적으면 놓친다.
  - 따라서 동의서는 "이름 등이 포함될 수 있음"을 전제로 받는다.

| `WORKER_DISPATCH_TOKEN` | **최우선 확인** — 없으면 워커가 수 시간~하루 넘게 돌지 않음 (§1.1) |
| `STT_ENABLED` | `true` |
| `STT_SOURCE_URL_SECONDS` | `86400` (또는 비움 = 기본 86400) |
| `AI_PROVIDER`, `AI_SUMMARY_ENABLED`, `AI_PROVIDER_TERMS_CONFIRMED`, `AI_TEENS_ENABLED`, `AI_TEEN_GUARDIAN_REQUIRED`, `AI_UNDER14_ENABLED`, `AI_ZDR_APPROVED` | **GitHub Actions와 같은 값** |
| `OPENAI_API_KEY`, `GEMINI_API_KEY` | **넣지 않음** |

확인 방법: `GET https://<Render>/api/v1/meta/ai-features` → `ai_provider: "openai"`, 설정 후 `ai_summary: true`, `ai_summary_status: "ENABLED"`.

## 7. 실제 활성화 절차

### 7.1 남은 단계 (성인부터)

1. 이 PR 병합 → **운영 DB에 0013 적용**(별도 승인) → Render·Vercel 배포

### 7.2 성인 테스트 계정으로 실제 호출 (유료 호출 승인 후)

1. 실제 학생이 아닌 **테스트 계정** 생성 → 동의 화면에서 성인 생년월로 동의
2. 실제 학생 목소리가 아닌 **합성(TTS) 첨삭 녹음**으로 녹음 → 글로 바꾸기
3. 대본 완료 → 요약 작업 생성 → 워커 즉시 실행(또는 수동: `gh workflow run stt-worker.yml -f max_jobs=1`)
4. 확인할 것:
   - 워커 로그 `"llm": "gpt-6.1-terra"`, `job processed`
   - 카드 "AI 첨삭 정리 보기"
   - DB의 `ai_processing_jobs.input_tokens/output_tokens/api_call_count`
   - OpenAI 사용량 화면
5. 문제 시 즉시 `AI_SUMMARY_ENABLED=false` (Render·Actions 둘 다)

### 7.3 만 14~17세 활성화 조건

1. ⚖️ 법률 검토:
   - 국외 이전 별도 동의 항목 충족
   - 연령 자기 입력의 허용 여부
   - 청소년 대상 고지의 적정성
2. OpenAI 비즈니스 약관 원문에서 18세 미만 보호자 조항 확인 → 있으면 `AI_TEEN_GUARDIAN_REQUIRED=true`(보호자 링크 사용)
3. OpenAI 미성년자 보호조치 보완: 부적절한 결과 신고 경로(§2.4 미구현), 필요하면 moderation
4. 성인 단계에서 품질·비용 확인 후 `AI_TEENS_ENABLED=true`(Render·Actions 같은 값)

### 7.4 만 14세 미만 (당분간 차단)
